# LinkExt V2.3.2 — déploiement

## Variables Vercel existantes
- FIREBASE_PROJECT_ID
- FIREBASE_CLIENT_EMAIL
- FIREBASE_PRIVATE_KEY
- CLOUDINARY_CLOUD_NAME
- CLOUDINARY_API_KEY
- CLOUDINARY_API_SECRET
- APP_ORIGIN
- RATE_LIMIT_SALT

## Nouvelles variables nécessaires

### OTP Gmail (Nodemailer)
Variables prioritaires (cahier des charges V3.3) :
- EMAIL_USER=adresse Gmail d'envoi
- EMAIL_PASS=mot de passe d'application Gmail

Fallbacks acceptés :
- SMTP_HOST=smtp.gmail.com
- SMTP_PORT=465
- SMTP_SECURE=true
- SMTP_USER=adresse Gmail d'envoi
- SMTP_PASS=mot de passe d'application Gmail
- SMTP_FROM=adresse d'envoi
- ADMIN_EMAIL=adresse qui reçoit les notifications de nouveaux recours (optionnel)

Ne jamais utiliser le mot de passe Gmail principal. Utiliser un App Password SMTP.

### Recours / OTP
- Collection Firestore `recours` (statut: en_attente | approuve | rejete)
- Collection `otp_requests` et `otp_challenges` (écritures côté Admin SDK uniquement)
- Code OTP : 5 caractères alphanumériques (A-Z0-9), validité 10 minutes

### Cron de nettoyage
- CRON_SECRET=secret long et aléatoire

### Agent IA
Deux possibilités :
- AI_API_KEY + AI_API_KEY_HEADER (optionnel)
- ou GEMINI_API_KEY

Le nom du modèle, l'URL du fournisseur et le prompt ne sont pas codés dans le frontend/backend : ils sont enregistrés dans `system_config/ai`.

Document Firestore `system_config/ai` :
- primary_model_name
- fallback_model_name
- ai_provider_url
- moderation_prompt

Si `ai_provider_url` contient `{model}`, le nom du modèle configuré est injecté dans cette URL.

## Firestore
Déployer :
- `firestore.rules`
- `firestore.indexes.json`

## Cron
`vercel.json` programme `/api/cron-cleanup` quotidiennement à 03:00 UTC.

Le cron exige `Authorization: Bearer <CRON_SECRET>`.

## Remarque quota
Les panneaux admin n'utilisent plus de liste globale des utilisateurs.
Les historiques sont limités.
Les lectures publiques du profil utilisent le cache Vercel.
Les listeners admin sont immédiatement désabonnés après leur lecture initiale.
La reconnexion réseau ne déclenche plus de synchronisation Firestore automatique.


## V3.4 — Recours OTP & sécurité
- Collection unique `appeals` (plus de `recours`)
- Soumission uniquement via `/api/submit-appeal` (Admin SDK)
- Rate limit OTP : 3 / 10 min — message 429 standard
- Un seul recours `en_attente` par compte
- CORS : `https://linktreepro.vercel.app` + prévisualisations `*.vercel.app`
- Cron : purge OTP / appeal_verifications expirés
- Variables : `EMAIL_USER`, `EMAIL_PASS` (obligatoires pour l’envoi), `ADMIN_EMAIL` (optionnel)


## V3.7 — Modération, recours et correction obligatoire
- `admin_settings/moderation` contient les règles de détection, le statut de sanction, les durées de suspension et les paramètres de nettoyage.
- `/recours` centralise désormais la file administrateur et le dossier utilisateur.
- L’approbation conditionnelle active une correction obligatoire contrôlée côté serveur.
- `banReasonReport` est enregistré sur le profil sanctionné et dans le journal de modération.
- Les signalements peuvent être supprimés définitivement depuis `/admin` après confirmation.
- Le nettoyage quotidien réactive les suspensions arrivées à échéance et applique les durées configurées.
## V3.8 — Corrections ciblées

- Interface `/admin` nettoyée des doublons de recherche utilisateur, paramètres de badges et signalements.
- Route `/signaler-bug` différenciée par rôle : soumission utilisateur ou gestion administrative.
- Gestion des recours centralisée sur `/recours`.
- Statut `CORRECTION_PENDING` avec verrouillage serveur du parcours de correction.
- Questionnaire d’examen IA optionnel, configurable en base de données.
- Configuration IA étendue : modèle, endpoint, accès par variable d’environnement, template de requête, chemin de réponse, consignes, comportement d’indisponibilité et paramètres de sanction.
- Aucune clé secrète n’est embarquée côté client.
